# Timio v0.5.4 — real WhatsApp / SMS / Email providers

## Providers
- Telegram: existing real Bot API integration.
- WhatsApp: Twilio WhatsApp Business Platform using an approved Content Template.
- SMS: Twilio Programmable Messaging.
- Email: Resend transactional email API.

## Backend environment
```env
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_SMS_FROM=+15551234567
TWILIO_WHATSAPP_FROM=+15551234567
TWILIO_WHATSAPP_CONTENT_SID=HX...
TWILIO_WHATSAPP_CONTENT_VARIABLES={"1":"clientName","2":"time"}
RESEND_API_KEY=re_...
RESEND_FROM=Timio <notifications@yourdomain.com>
```

Credentials stay on the backend.

## WhatsApp
Business-initiated WhatsApp reminders use an approved template. Map its variables with `TWILIO_WHATSAPP_CONTENT_VARIABLES`. Recipient phones must be E.164. Explicit WhatsApp opt-in/opt-out must be collected and respected before production messaging. Twilio Sandbox can be used for initial development; production requires a registered WhatsApp sender/WABA.

## SMS
Set `TWILIO_SMS_FROM` to a sender allowed for the destination country.

## Email
Set `RESEND_FROM` to a verified sending identity/domain.

## Testing
Open `Настройки → Уведомления`, refresh provider status, choose a client and channel, then press `Отправить тест`. The request goes from the Timio backend to the real provider.

## Multi-tenant note
This release uses platform-level Twilio/Resend credentials. That is suitable for MVP/testing and a controlled pilot. Before broad multi-business production, WhatsApp sender onboarding should become business-specific and explicit messaging consent should be stored per client/channel.

## Verification
A complete Nuxt production build cannot be claimed in this environment because the optional native OXC dependency set is incomplete.
