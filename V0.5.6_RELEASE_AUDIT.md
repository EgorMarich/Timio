# Timio v0.5.6 — Release Audit

## Goal

Harden the MVP before moving to the responsive/mobile pass in v0.6.

## Implemented in v0.5.6

### Public booking integrity
- Public booking now validates the requested time against Timio's generated availability for the business timezone, service and staff.
- The existing database overlap check remains as the final race-condition guard.
- Invalid business timezones are rejected instead of silently calculating slots in the wrong timezone.

### Waitlist tenant isolation
- Public waitlist validates that the business exists.
- Service must belong to that business.
- Optional staff must belong to that business and support the selected service.
- Supplied client IDs are accepted only when the client belongs to the same business.
- Start/end timestamps must be valid and match the service duration.

### Onboarding validation
- Business creation validates IANA timezone values.
- Business name/slug generation uses the trimmed business name.

## Audit findings carried forward

### P0 / production blockers
- Replace browser localStorage JWT with HttpOnly secure session cookies.
- Encrypt Telegram bot tokens at rest.
- Add provider delivery webhooks and durable retry/backoff.
- Add per-client messaging consent/opt-out, especially for WhatsApp/SMS.
- Move WhatsApp sender configuration from platform-global credentials to business-level onboarding.
- Add rate limiting / abuse protection to public booking, availability and waitlist endpoints.
- Add CI with real dependency installation and type/build checks.

### P1
- Move photos from base64/data URLs to object storage/CDN.
- Add phone normalization/E.164 validation.
- Add database-level constraints/indexes for notification settings and appointment lookup paths.
- Split the monolithic dashboard page into feature components.
- Consolidate legacy duplicate dashboard routes.
- Move reminder/campaign execution to a durable queue such as BullMQ.

## Release decision

**v0.5.6 is an audit/hardening release, not a production certification.**

The application remains suitable for continued product development and local/staging testing. External provider credentials are intentionally not required for this release.

## Next

`v0.6 → Responsive/Mobile First + PWA shell → Growth/Retention → AI Business OS`

### Business timezone correctness
- Availability slot generation now converts the requested business-local date to UTC explicitly instead of relying on the API server's local timezone.
- Weekday/date boundaries are derived from the business calendar, preventing cross-timezone booking drift.
