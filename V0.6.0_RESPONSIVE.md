# Timio v0.6.0 — Responsive Architecture

## Goal

Make the Timio dashboard a first-class mobile workspace instead of a compressed desktop layout.

## Delivered

- Desktop sidebar is hidden on small screens and replaced by a fixed mobile bottom navigation.
- Primary mobile navigation exposes Today, Schedule, Clients and Services.
- Remaining areas are available from a mobile “Ещё” sheet: Staff, Analytics, Marketing, Notifications, Team, Billing, Settings and Archive.
- Mobile navigation respects safe-area insets for modern phones.
- Modal dialogs become bottom sheets on phones and use the available viewport height.
- Appointment detail actions become a two-column mobile action grid.
- Dashboard hero/actions stack vertically on narrow screens.
- Schedule remains horizontally scrollable by staff instead of collapsing staff columns into an unusable vertical list.
- Client list removes secondary statistics on narrow screens while keeping name/contact and navigation.
- Analytics and two-column form layouts collapse for small screens.
- Service/staff creation layouts stack vertically on phones.
- Main content width/padding is responsive at tablet and phone breakpoints.
- Added `mobile-sheet` transition for the extra navigation sheet.

## Navigation model

```text
Desktop
Sidebar → all workspace sections

Mobile

    └── Архив
```

## Deliberate decisions

### Schedule
The staff-column schedule stays horizontally scrollable on mobile. This preserves the mental model of “one column = one employee” and avoids turning a working calendar into a long unreadable feed.

### Modals
On phones modals behave like bottom sheets. This gives more vertical room for appointment forms and CRM details while retaining the existing reusable `Modal.vue` component.

### Primary actions
The mobile navigation prioritizes the daily loop: Today → Schedule → Clients → Services. Secondary administration is one tap deeper.
