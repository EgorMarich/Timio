# Timio v0.6.2 — Mobile CRM + Daily Operations

## Goal

Make the client card useful as a daily mobile workspace rather than a desktop-style information modal.

## Delivered

- Mobile-first client profile header with initials/avatar treatment.
- Quick actions for phone, email and repeat booking.
- Client KPIs: visits, total spent and last visit.
- Next appointment highlighted at the top of the card.
- Direct navigation from client history to the corresponding appointment.
- Repeat booking from the latest completed visit.
- Tags and notes editing redesigned for touch input.
- Sticky save action on mobile so CRM changes can be committed without scrolling back.
- History redesigned as compact timeline-like rows instead of dense desktop rows.
- Keyboard activation retained for history rows.
- Loading skeleton for the client card.
- Responsive layout for small phones, tablets and desktop modal widths.

## Daily flow

```text
Today
  ↓
Appointment
  ↓
Client
  ├── call / email
  ├── next appointment
  ├── CRM tags / notes
  ├── visit history
  └── repeat booking
```

## Architecture note

This release intentionally reuses the existing appointment and CRM APIs. No duplicate mobile-only data model was introduced. The next refactoring stage can extract the client card into a dedicated feature/component without changing its API contract.

## Known limitations

- Contact data remains read-only from the business dashboard; the client controls phone/email/Telegram data.
- Repeat booking still opens the existing appointment form and reuses the existing service/staff selection flow.
- Full frontend production build is not claimed in this environment because the repository dependencies/native bindings are not installed completely.
