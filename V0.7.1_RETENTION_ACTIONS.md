# Timio v0.7.1 — Retention Actions

## Цель
Связать Retention/Reactivation Engine с Campaign Engine: из найденного сегмента можно сразу создать персонализированную кампанию и подготовить её к отправке.

## Что добавлено

### 1. Reactivation → Campaign
- сегменты `all`, `due`, `at_risk`, `lost` теперь доступны как отдельный тип кампании `reactivation`;
- кнопки «Создать рассылку» автоматически заполняют название, сегмент и базовый персонализированный текст;
- клиентские переменные `{{clientName}}` и `{{businessName}}` продолжают поддерживаться.

### 2. Preview получателей
- preview использует тот же deterministic Reactivation Engine, что и dashboard;
- в выборку попадают только клиенты с подключённым Telegram;
- повторная реактивация одного клиента блокируется на 14 дней после предыдущей retention-кампании.

### 3. Recipient snapshot
При отправке retention-кампании в `filters.recipientIds` сохраняется snapshot получателей. Это даёт:
- защиту от повторного контакта;
- воспроизводимую историю того, кому предназначалась кампания;
- основу для будущей полноценной таблицы campaign recipients.

### 4. Каналы
UI уже показывает модель выбора канала:
- Telegram — доступен сейчас;
- WhatsApp — скоро;
- SMS — скоро;
- Email — скоро.

Backend намеренно принимает сейчас только `telegram`, чтобы UI не создавал иллюзию работающей доставки без provider credentials.

## Поток

`Retention Engine → segment → recipient preview → personalized message → channel → Campaign → Telegram delivery`

## Ограничения MVP
- отправка по-прежнему Telegram-only;
- cooldown хранится через snapshot в JSONB кампании, отдельной таблицы доставок/получателей пока нет;
- AI не принимает решение о сегментации — алгоритм остаётся детерминированным и прозрачным.
