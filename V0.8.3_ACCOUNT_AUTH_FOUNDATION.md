# Timio v0.8.3 — Account & Auth Foundation

## Implemented

- Replaced browser `localStorage` JWT authentication with Redis-backed opaque sessions.
- Session cookie: HttpOnly, SameSite=Lax; Secure in production; production uses `__Host-` cookie naming.
- Added account lifecycle: `pending_email_verification`, `active`, `suspended`, `deleted`.
- Added email verification tokens: single-use, hashed at rest, 24h expiry.
- Added resend verification flow with Redis rate limiting.
- Added password reset: generic request response, single-use hashed token, 30m expiry, session invalidation after reset.
- Added Google and VK OAuth entry/callback routes. OAuth accounts link to an existing account by verified provider email instead of creating duplicates.
- Added `user_identities` and `auth_tokens` tables.
- Added `emailVerifiedAt` and `lastLoginAt`.
- Added frontend flows for login, registration, email verification, forgot password, reset password and OAuth buttons.
- Development mode exposes verification/reset URLs when Resend is not configured, so local development is not blocked by provider credentials. Production never exposes those URLs.
- CORS now allows credentialed requests for cookie sessions.

## Environment

Required for production email verification/reset:
- `RESEND_API_KEY`
- `RESEND_FROM`
- `FRONTEND_URL`
- `API_PUBLIC_URL`

OAuth:
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `VK_CLIENT_ID`
- `VK_CLIENT_SECRET`

The provider callback URLs are:
- `/auth/oauth/google/callback`
- `/auth/oauth/vk/callback`

## Security notes

The implementation follows the main OWASP session guidance: authentication session identifiers are not stored in browser storage; the server owns session state; production cookies use Secure + HttpOnly + SameSite; password reset tokens are random, single-use and time-limited.

## Not included yet

- MFA.
- Device/session management UI.
- Production OAuth provider verification/configuration.
- Dedicated distributed rate-limit middleware for all public API endpoints.
