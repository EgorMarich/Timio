# Timio v0.8.4 — Auth Hardening

## Goal
Strengthen the v0.8.3 account foundation before onboarding, billing, team permissions and further AI work.

## Included
- Redis sessions now keep creation time, last activity, IP and user-agent metadata.
- Session activity is refreshed on authenticated API requests.
- Active sessions can be listed and individually revoked.
- Users can revoke all other sessions.
- Password change requires the current password, enforces the stronger password policy and rotates the session.
- Password reset invalidates all existing sessions.
- Email change requires verification of the new address and rotates sessions after confirmation.
- Login is rate-limited by both IP and normalized email.
- Password/email security actions have additional rate limits.
- Authentication audit events are persisted in PostgreSQL.
- Account security UI shows active sessions and the security event log.
- State-changing cookie-authenticated requests are checked against configured CORS origins in addition to SameSite cookies.
- Added security headers already present in the API are retained.

## Password policy
New passwords must be at least 10 characters and contain both letters and numbers.

## New API
- `GET /auth/sessions`
- `DELETE /auth/sessions/:sessionId`
- `POST /auth/sessions/revoke-others`
- `POST /auth/change-password`
- `POST /auth/request-email-change`
- `POST /auth/confirm-email-change`
- `GET /auth/audit-events`

## Database
Migration: `backend/src/db/migrations/0005_auth_hardening.sql`

Adds `auth_audit_events` and supporting indexes.

## Important production note
The session store is Redis-backed. Redis persistence, TLS/network isolation, secret management and operational monitoring remain deployment responsibilities. OAuth provider credentials and a production email provider are still required for real external login/email delivery.
